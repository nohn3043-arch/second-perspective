# 上海合规说明 — 全球认知审计引擎（GCAE）

> 本说明面向上海监管与部署场景，对 GCAE 的监管定位、数据出境与部署基线作出说明。
> **本文件为草案框架，正式商用前应由法律顾问终审。**

## 一、监管定位

GCAE 是本地运行的认知偏差审计引擎，核心五算子因果审计**完全离线运行**，不对外提供拟人化、持续情感互动或生成式公共服务，因此**不属于**《人工智能拟人化互动服务管理暂行办法》所列之拟人化互动服务形态，不触发相应备案义务。

- 核心审计流水线：离线、确定性、可本地验证，无云端调用。
- 输入决策数据默认不上传任何服务器。

## 二、数据出境合规重点（最高风险项）

GCAE 附带可选 LLM 增强分析（OpenAI 兼容适配器），**默认关闭**。启用时必须满足以下全部条件：

1. **境内端点**：将 `base_url`/`api_base` 指向境内模型端点（如 DeepSeek、通义千问），不得默认请求境外 `api.openai.com`。
2. **输入脱敏**：在构造 prompt 前对决策数据做脱敏（去除可识别个人信息与敏感业务数据）。
3. **用户同意**：明确告知数据用途并取得用户同意。
4. **出境安全评估**：如确需调用境外端点，须依法开展个人信息/重要数据出境安全评估并完成备案。

## 三、生产部署基线

- **P1 数据安全**：本地存储加密、访问控制、最小权限；敏感决策数据默认不落库。
- **P2 审计证据链**：生成 `audit_id` 与签名哈希，证据可验证、可追溯、可还原。
- **P3 治理配套**：部署方应建立内容红线、异常处置与人工复核机制。

## 四、禁止事项

- 未经脱敏将个人/敏感决策数据发送至境外端点。
- 对审计结果作虚假"完全无云端"宣传而实际启用境外 LLM 调用。
- 移除证书签名或篡改报告以规避责任。
